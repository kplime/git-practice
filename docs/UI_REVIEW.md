# 온가드(OnGuard) 모바일 화면 검토 · 2026-10-07

현재 범위는 한 공간의 보호자 모바일 웹이다. 상시 운영하며 특정 질환·야간으로 한정하지 않는다. 샘플을 포함한 개발 상태와 실제 사용에 필요한 다음 작업을 구분한다.

소개서 기준 프로젝트 설명은 [프로젝트 설명](./PROJECT_PLAN.md)에 정리했다. 아래 내용은 현재 구현된 화면의 동작과 검증 기록이다.

| 화면/기능 | 보완 내용 |
|---|---|

| 홈 | 통신만 살아 있는 경우를 정상으로 표시하던 문제 수정. 오래된 측정·센싱 중단·품질 저하에서는 현재 침대 추정 숨김. 미확인 사건이 있을 때만 경고 카드, 없으면 일반 카드. 조회 실패를 사건 없음으로 표시하지 않음 |
| 침대 상태 | 관측이 유효하고 이탈 시작 시각이 있을 때 경과 시간 표시. 현재 적용을 확인한 기준만 함께 표시 |
| 사건 목록 | 맨 위 유형 구분. 처리 상태와 기간 조회를 하나의 '조회 조건'으로 묶고 기본 접힘. 시작·종료 날짜와 선택 시각 입력. 시각 미지정은 날짜 전체, 종료 시각 지정은 해당 분 전체 포함. 접힌 상태에도 상태·날짜·시각 표시. 필터 변경 시 커서 초기화. 날짜별 사건 묶음과 오늘 표시, 처리 기록·해소 사유 요약 추가. 다음 페이지가 같은 날짜이면 기존 묶음에 합치며 eventId 중복 제거. 처리 상태 안내는 별도로 접어 표시 |
| 상세 | 확인과 상황 해소 분리. 미확인은 경고색, 확인됨은 파란색, 해소됨은 녹색 카드. 해소된 사건은 입력 폼 숨기고 저장한 사유·이력 표시. 상황 해소 버튼은 비활성 시 회색, 직접 확인과 사유 입력 후 빨간색으로 표시. 발생·감지와 별도로 실제 서버 수신 시각 표시. 서버 저장 이력을 푸시 전달 이력으로 표시하지 않음 |
| 감지 설정 | 기기 상태 → 미복귀 → 낙상 의심 → 기기 장애 → 저장 순서. 제목과 내부 문구를 감지로 통일. 상시는 시간 입력을 숨기고 지정 시간 선택 시 표시. 미복귀 기준과 한국 시간·자정 넘김 지원. 낙상·센싱 장애·통신 장애를 독립 저장. 미저장·저장 중·저장 완료·기기 적용 대기를 구분. 입력을 원래 값으로 돌리면 미저장 표시 제거. 자동 갱신 중 입력과 저장 피드백 보존 |
| 알림 | '이 브라우저 알림' 켜기·끄기 스위치 추가. 선택은 localStorage에 저장하고 같은 사이트의 다른 탭에도 반영. 끄면 새 표시 요청을 차단하고 준비 중인 요청과 늦게 완료된 요청을 취소·닫기 처리. 저장 불가 시 성공으로 표시하지 않음. 브라우저 권한과 원격 수신 상태는 별도로 유지. 표시 요청 성공 후 사용자가 직접 확인해야 '표시 확인됨' 표시. 기기·브라우저 이름은 현재 브라우저 정보로 표시하며 계정·구독 등록을 의미하지 않음. 원격 수신 미연결과 로컬 표시 확인의 차이를 표시 |
| 모바일 기본 | 크림색 배경과 흰색 일반 카드를 전체 화면에 통일. 하단 메뉴 고정, 안전 영역·콘텐츠 하단 여백 유지. 분 단위와 숫자를 묶은 입력 유지. 토글 행 최소 높이 48px, 뒤로 가기·직접 확인 영역 44px. 꺼진 토글 윤곽·입력 테두리 강화. 목록은 유형·상태·발생 시각 중심, 긴 설명은 상세에 표시 |
| 상세 화면 이동 | 주소만 바뀌고 화면이 전환되지 않는 문제 수정. 활성 화면을 JS에서 직접 지정하고 나머지 화면을 숨김. 직접 상세 주소, 뒤로/앞으로 이동도 동일하게 처리 |
| 상단 브랜드 | '온가드(OnGuard) · 보호자 모바일 웹' 영역을 상단에 붙여 모든 화면과 스크롤 중 표시. 휴대폰 상단 안전 영역과 화면 앵커 이동 여백 적용. 실제 휴대폰 스크롤 확인은 남아 있음 |

상세 링크는 history.pushState로 URL을 바꾸지만 기존 CSS는 :target에 의존했다. pushState는 문서의 CSS target을 갱신하지 않으므로 API 응답이 정상이어도 상세 section이 숨겨질 수 있었다. 이제 route에서 active 클래스·hidden 속성과 하단 메뉴 상태를 함께 지정한다. [MDN :target](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:target).

### Figma 초안에서 추가로 반영한 내용

- 아이콘은 사용자가 제공한 초안 HTML의 SVG 심볼을 사용한다. 낙상 의심은 경고 삼각형, 미복귀는 침대, 센싱 장애는 Wi-Fi, 기기 통신 장애는 모니터로 구분한다. 침대 상태·감지 설정·사용 기기에도 같은 선 형태의 아이콘을 적용한다. 아이콘은 장식으로 숨기고 텍스트 유형·처리 상태를 유지한다. 하단 메뉴와 관측 상태도 같은 SVG 심볼을 사용한다.
- 홈은 실제 측정 데이터의 경과 초와 조회 시각을 표시한다. 침대 이탈 추정 시각은 유효한 실제 관측과 이탈 상태일 때만 표시한다. 조회 실패 시 최신 관측을 확인하지 못했다고 표시한다.
- 감지 설정의 저장 버전·기기 적용 버전 숫자는 화면에서 제거했다. 기기 상태 카드의 적용 상태와 마지막 저장 시각으로 안내한다. 내부적으로는 실제 기기가 연결되어 있고 보고한 적용 버전이 저장 버전과 같아야 '적용됨'으로 판단한다.
- 홈 사건 요약은 짧게 유지하고 목록에 처리 기록·해소 사유를 표시한다. 긴 사유는 두 줄로 줄여 표시하며 전체 내용은 상세 화면에서 확인한다.
- 푸시 서비스 접수 이력, 구독 켜기·끄기·재구독, 홈 화면 설치 버튼은 실제 기능이 연결되지 않아 이번 UI 반영 범위에 포함하지 않는다.

샘플 실행법은 [README](../README.md#화면-확인용-샘플-데이터)를 따른다. DB에서 `is_demo=true`, `payload_json.details.source=ui-sample-v1`로 구분한다. UI에는 개발 설명을 넣지 않는다. 기본 샘플 명령은 사건 기록만 생성한다. 상태 시뮬레이터는 `--heartbeat`를 명시할 때만 실행하며, 모든 테스트 신호는 서버의 현재 관측 조회와 웹의 정상·측정 시각·침대 추정·기기 적용 판정에서 제외한다. 실제 신호가 없으면 연결 대기, 있던 실제 신호가 오래되면 연결 끊김으로 판단한다.

## 소개서의 구현 전 기능

소개서의 실제 CSI 수집·로컬 AI 분석, 낙상 유사 동작 구분, 장시간 저활동 감지, 원격 보호자 알림과 실시간 활동 지표는 구현 전이다. 사건 목록의 시험 기록은 실제 감지가 실행되었다는 증거가 아니다.

## 검증 결과

- `npm.cmd test`: 2026-10-07 DOM 기반 29개 통과. 기존 기능·날짜/시각 조회·접힘·상세 이동·설정 독립 저장에 더해 상황 해소 버튼의 활성/비활성 색상, 사건 상태별 카드, 홈의 사건 없음과 조회 실패 구분, 미저장·원래 값 복원·저장 중·저장 후 기기 적용 상태 및 주기 갱신 시 피드백 보존을 검증. 정상으로 보이는 시험 신호나 출처 구분이 없는 응답에서도 관측·측정 시각·설정 적용을 인정하지 않고 실제 신호 응답에서만 재개하는 것을 검증. Figma 반영 후 날짜 묶음의 페이지 경계 합침·중복 제거, 해소 사유의 HTML 삽입 차단, 서버 수신 시각, 실제 신호의 경과 시간·설정 적용 상태와 시험 신호·조회 실패 시 처리, 기기 정보·알림 권한이 원격 수신 완료로 이어지지 않는 것을 추가 검증. 알림 스위치의 저장·재열기·권한 조건, 준비 중 끄기, 표시 완료가 늦게 돌아오는 경우, 다른 탭 반영과 저장 실패 처리를 추가 검증. 이번 알림 변경은 서버·DB 코드를 수정하지 않아 통합 검증은 재실행하지 않음.
- Python 감지 정책 8개 통과. 한국 시간·자정 넘김·시간 경계·끄기·상시·유형별 독립 제어와 함께, 해제한 유형의 새 사건 전송 차단, 측정 상태 전송과 기존 사건 재전송 유지, 알 수 없는 유형 거절을 검증. 통합 검증에서 함께 실행한다.
- `npm.cmd run test:integration`: 임시 PostgreSQL 스키마·별도 Express 서버에서 통과. Python API 전송, 인증·순번·중복, 상태 확장·측정 신선도, 설정, 처리, 페이지 이동, 24개 샘플·재실행 보존, 기간 자정 경계·커서/유형/상태 결합·잘못된 기간 입력을 검증. 새 알림 옵션의 기본값·부분 수정·게이트웨이 전달·잘못된 값 거절·기존 사건 보존도 검증.
- DOM/API 검증은 실제 휴대폰의 화면 배치·시스템 알림·백그라운드 Push 검증을 대신하지 않는다.
- 로컬 3002 서버에서 샘플 사건 24개를 유지하며 현재 연결 false, 센싱 false, 신선도 false, 침대 UNKNOWN, 측정·수신 시각과 적용 버전 null을 확인했다. 통합 검증에서는 실제 신호 수신·기한 경과와 최신 시험 신호의 관측 제외를 확인했다. 연결 가능한 브라우저가 없어 실제 화면 렌더링과 시스템 알림은 이번에 검증하지 못했다.
- 후속 수정은 실제 로컬 서버의 HTML/CSS/JS와 API를 연결한 DOM 검증으로 2026-10-06 하루의 사건 6개 조회 및 상세 화면 표시를 확인했다. 실제 브라우저 연결은 여전히 없어 휴대폰 렌더링 검증은 남아 있다.

[MDN showNotification](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/showNotification). 원격 수신에는 활성 Service Worker와 Push 구독·서버 전송이 필요하다.
